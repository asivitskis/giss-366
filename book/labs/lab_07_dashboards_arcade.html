Lab 7#

ArcGIS Dashboards and Arcade#

GISS/GEOG 366/368 · Web Mapping & Web GIS#

How this lab works: You build a dashboard in ArcGIS Dashboards from a data option you choose, link its elements together, and add Arcade to it. The Week 9 page and Thursday’s session give you the concepts and starter expressions. This lab page tells you what to build, what to notice while you work, and what to submit. Most of the work is self-paced, so see the pacing guide below.

Shortened cycle: Lab 7 uses the shorter version of the Ask, Collect, Visualize, Create, Act cycle again: Ask (a quick prediction and plan), Build (the dashboard and your Arcade), and Act (submit and reflect).

Step 1: Ask#

Before you build, write down your first-pass answers. Do not look anything up. You will revisit these in your reflection.

  • Audience and decision: Which data option will you choose (see Step 2), and why? Write one sentence naming your audience and one decision your dashboard could help them make.

  • Plan: Which Arcade tier will you aim for? Which part do you expect to be easy, and which part do you expect to be hard?

  • Gap: Name one thing you wish a configuration panel could do with your data and cannot.

Lab 7 Question: Arcade puts a small amount of code inside a tool that otherwise needs none. Before you start, what do you expect it will let you do that settings alone cannot, and what new risk does writing code add?

Step 2: Build#

Part A: Choose your data and make a web map#

Pick one option. All three work with the same required elements, and the tiers apply to each.

Option

Layer

Good for

A: Current wildfires

USA Current Wildfires from ArcGIS Living Atlas (use the Current Incidents sublayer). This is the same source as Tuesday’s dashboard.

An operational dashboard. Look for a state or cause field, an acres field, and a discovery date.

B: Recent earthquakes

Recent Earthquakes from ArcGIS Living Atlas (use the Events by Magnitude sublayer).

A monitoring dashboard. Look for magnitude, hours since the event, and an alert level.

C: Your own data

The hosted feature layer from Lab 1, or another layer you propose. Post the layer link on the discussion board for a quick approval before you build.

A dashboard about a place or topic you care about.

Field checklist for any option: at least one category field with roughly 3 to 10 values, at least one numeric field, and at least 30 features. A date field is helpful if you want to write time-based Arcade. Open the layer’s table and confirm these before you commit.

Steps:

  1. In ArcGIS Online, find your layer (for A and B, search Living Atlas), open it in Map Viewer, and zoom to a useful extent.

  2. Save the web map as Lab7__<A, B, or C>. Use this naming pattern for the dashboard too, because I will use it to find your work in our organization.

  3. Create the dashboard from your saved web map the same way you did on Tuesday (Create app, then Dashboards).

Live layers change by the hour, so the numbers on your dashboard will differ from your classmates’ and from your screenshots later. Do not copy specific numbers into your reflection.

Part C: Add Arcade#

Choose a tier. Tier 1 is required. Tier 2 or Tier 3 is how you reach the top band of the rubric. Whichever tier you choose, give each expression a title, add a comment line that states what it decides, and keep a copy of the text for your submission.

Tier

What you write

What it adds

1 (required)

A formatting expression on the indicator, list, or table

Color, text, or an icon that responds to the values

2

A data expression that uses GroupBy

A summary by group that feeds a chart or list

3

A data expression with a loop

A new field the data never had, such as a size or severity class

What Tier 1 must include: a condition (When, IIf, or Decode) tied to a threshold or category you can justify to your audience, and text that carries the same message as the color. Do not rely on color alone.

A note on field names. The starter expressions below use placeholder names. Open the Profile Variables panel (Tier 1) or the layer’s table (Tiers 2 and 3) and use your layer’s real names. Run after every change.

Tier 1 starter: indicator. Click to expand 
// Indicator: how busy is it right now?
var n = $datapoint.count_IncidentName;   // use the exact name from the Profile Variables panel
var color = When(n >= 50, '#b8312f', n >= 20, '#d98a00', '#2e7d32');
var label = When(n >= 50, 'High activity', n >= 20, 'Moderate activity', 'Low activity');

return {
  topText: 'Current wildfires in view',
  middleText: Text(n, '#,###'),
  middleTextColor: color,
  bottomText: label,
  bottomTextColor: color
};

For Option B, count earthquakes and base the thresholds on a number your audience would care about. For Option C, choose thresholds that make sense for your own data.

Tier 1 starter: list. Click to expand 
// List: shade the biggest rows and add a size class to the template
var size = $datapoint.CalculatedAcres;   // swap in a numeric field from your layer
var sizeClass = When(size >= 10000, 'Major', size >= 1000, 'Large', 'Small');
var shade = When(size >= 10000, '#F3DED7', size >= 1000, '#FBEFD5', '');

return {
  backgroundColor: shade,
  attributes: {
    sizeClass: sizeClass
  }
};

Then set the list template to use the new attribute, for example {IncidentName} ({expression/sizeClass}).

Tier 2 starter: summarize by group. Click to expand 
// Data expression: incidents and total acres for each state
var fs = FeatureSetByPortalItem(
  Portal('https://www.arcgis.com'),
  'YOUR_ITEM_ID',     // from the item page address, after id=
  0,                  // sublayer number, the number at the end of the layer address
  ['*'],
  false
);

return GroupBy(
  fs,
  ['POOState'],       // the field to group by
  [
    { name: 'incidents', expression: '1', statistic: 'COUNT' },
    { name: 'total_acres', expression: 'IncidentSize', statistic: 'SUM' }
  ]
);

To use it, open a chart’s data source window, choose New data expression, paste the expression, click Run, and name it. Set the chart’s category to your group field and its series to one of the new statistics.

Tier 3 starter: derive a new field. Click to expand 
// Data expression: add a size class the layer does not have
var fs = FeatureSetByPortalItem(
  Portal('https://www.arcgis.com'), 'YOUR_ITEM_ID', 0, ['*'], false
);

var rows = [];
for (var f in fs) {
  var acres = IIf(IsEmpty(f.IncidentSize), 0, f.IncidentSize);
  var sizeClass = When(
    acres >= 10000, 'Major (10,000 acres or more)',
    acres >= 1000, 'Large (1,000 to 9,999)',
    'Small (under 1,000)'
  );
  Push(rows, { attributes: { name: f.IncidentName, acres: acres, sizeClass: sizeClass } });
}

var out = {
  fields: [
    { name: 'name', type: 'esriFieldTypeString' },
    { name: 'acres', type: 'esriFieldTypeDouble' },
    { name: 'sizeClass', type: 'esriFieldTypeString' }
  ],
  geometryType: '',
  features: rows
};

return FeatureSet(Text(out));

A FeatureSet built this way has no map geometry, so it can feed a chart, list, table, indicator, or selector. The map keeps its own layers. Say what your thresholds are somewhere your audience can see them, for example in a chart title or an element caption.

Part D: Notice as you work. Click to expand

Keep these prompts in mind as you work. Jot notes if that helps, and nothing here is collected. They feed straight into your reflection questions.

  • Advanced formatting: When you switched it on, what happened to the settings that were already there?

  • Errors: What did the editor tell you when something was wrong, and what did you check first?

  • Decisions: Which parts of your expression are choices about your audience (thresholds, labels, colors), and which parts are mechanics?

  • Actions: Which link between elements surprised you? How would you have wired the same behavior in MapLibre?

  • Mobile: Look at your dashboard’s mobile preview. What moves, shrinks, or disappears?

  • Visitor test: Open your published dashboard in a private window. What did you see that you missed in the builder?

Pacing guide (adjust to your schedule). The core build with Tier 1 takes about 2 hours and 30 minutes. Tier 2 or Tier 3 adds roughly 45 minutes.

Sitting

Work

Goal

2 (about 60 min)

Elements 5 to 8

3 (about 45 min)

4 (about 30 min)

Test, share, and reflect

Published, tested as a visitor, submitted

Working rules:

  • Save as you go, and run your expression after every small change.

  • If something does not behave, treat it as a troubleshooting moment. Read the message, check the Profile Variables panel, and look the function up in the reference before you ask. Keep a note of what you tried, because you will describe one of these moments in your reflection.

  • Post questions on the discussion board so the answers help everyone.

Step 3: Act#

What to turn in (graded: Lab Exercises)#

  1. The link to your published dashboard, named with the Lab7__ pattern.

  2. Confirmation that your dashboard, its web map, and every layer behind it are shared with the organization or wider, so that your instructor can open it and see your work. Test this in a private window or on a second device. If you are unsure how to check, use the sharing guidance from Week 8, and tell me in your submission if something stopped you.

  3. The text of each Arcade expression you wrote, labeled with its tier. Paste it below your reflection. It does not count toward the word total.

  4. A short written reflection (~400 words total, roughly 60 to 70 words per question) answering:

    • What it did: Pick one expression. Say what it takes in, what it returns, and what the element does differently because of it. Name its tier.

    • Stuck and verified: Describe one error or surprise, how you found the cause (Run, Console, the Profile Variables panel), and one function you looked up in Esri’s reference. If you used an AI tool at any point, say how you checked what it suggested.

    • Audience and choices: Who is your audience, and what decision does your dashboard support? Pick one threshold, class, or color you chose. Who usually decides this kind of line, and how could it mislead a viewer?

    • Reach and access: Who can open your dashboard right now? What has to be true about the web map and layers behind it? Name one accessibility or device decision you made, how you tested it, and one barrier a real audience could still face.

    • Arcade and JavaScript: Name one thing Arcade shares with the MapLibre JavaScript you wrote and one thing that works differently. Where would you place Arcade on the continuum between a no-code builder and writing your own code?

    • Back to your prediction: Return to your Step 1 answers. What did you predict correctly, and what surprised you?

Submit your dashboard link, your expressions, and your written reflection to this week’s submission space in Canvas.

Lab 7 AI Policy: Level 2#

This lab permits optional use of AI to support student learning. Permitted uses can include using AI to help troubleshoot a step that is not working in ArcGIS Dashboards, to explain an Arcade error message in plainer language, or to explain a term or function from Esri’s documentation. AI tools often suggest Arcade functions or dictionary keys that do not exist, so anything an AI suggests must be checked against Esri’s reference or by running it in the editor, and you should be ready to describe how you checked it. However, independent installation and use of AI agents to complete GIS tasks is not permitted at this time. AI may also be used to support general writing procedures (outlining a response, improving clarity or grammar, etc.), but your reflection must remain original to you as the sole responsible author, and it must describe your own experience building your own dashboard. Disclosure of AI use is not required for this Level 2 assignment. Using AI is a choice with ethical considerations, and it is asked that students weigh those considerations accordingly as they complete this work.
